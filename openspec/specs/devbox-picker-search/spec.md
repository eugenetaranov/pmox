# devbox-picker-search Specification

## Purpose
How devbox-setup's picker searches its catalog and mise's registry as you type, and how tools picked from the registry are installed.
## Requirements
### Requirement: Type to search across tabs
The devbox-setup picker SHALL start a search when the user types a printable character other than space. While the query is non-empty:
- the tab bar SHALL be replaced by the query and the number of matches;
- the list SHALL show matching items from every tab, each with its category name, best match first;
- Backspace SHALL edit the query, space SHALL toggle the highlighted item, Enter SHALL go to Review;
- digits SHALL type into the query instead of switching tabs.

Esc SHALL clear a non-empty query and return to the tab the user was on. Esc on an empty query, or Ctrl-C, SHALL quit. Typing SHALL never change a selection.

#### Scenario: Searching zsh
- **WHEN** the user types `zsh` on any tab
- **THEN** the list shows the zsh, fzf-tab and other zsh-related items from Shell & CLI, labelled with their category, ahead of mise registry tools

#### Scenario: Clearing a search
- **WHEN** the user presses Esc with a query
- **THEN** the query is cleared, the tab bar returns on the previous tab, and selections made during the search are kept

### Requirement: Fuzzy matching
A query SHALL match an item when its characters appear in order, ignoring case, in the item's id, label or source (for registry tools: name, aliases or description). Exact and prefix name matches SHALL rank first, then matches at word starts, then longer consecutive runs; shorter text breaks ties, and catalog items rank before registry tools at equal score.

#### Scenario: Matching a description
- **WHEN** the user types `find`
- **THEN** mise's `fd` ("A simple, fast and user-friendly alternative to 'find'") is among the matches

### Requirement: mise registry in search
Search SHALL include mise's registry tools, which appear only in search results and in Review. devbox-setup SHALL take the registry from, in order: `mise registry` when mise is installed; pmox's full snapshot (with descriptions) fetched from the pmox repository, with a 5 second timeout and cached for a week; the names-only copy pmox ships. A failed fetch SHALL NOT stop the picker. A registry tool that a catalog item already installs with `mise use -g` SHALL be left out. A registry row SHALL show the tool name and the first sentence of its description on one line, without double-width characters.

#### Scenario: Fresh VM
- **WHEN** devbox-setup runs where mise is not installed
- **THEN** typing a mise tool name finds it, with its description when GitHub is reachable and by name alone when it is not

#### Scenario: Catalog tool not duplicated
- **WHEN** the user types `k9s`
- **THEN** only the Kubernetes CLIs catalog item matches k9s, not a separate registry row

### Requirement: Installing picked registry tools
Registry tools picked in the search SHALL be installed with `mise use -g <name>` as extra mise tools: they SHALL prefill the "Extra mise tools" prompt, which the user may edit (for example to add a version), and they SHALL be saved with the other extra mise tools for `--yes` re-runs. Picking one SHALL pull in mise.

#### Scenario: Picking a registry tool
- **WHEN** the user searches, ticks mise's `starship` and confirms
- **THEN** the "Extra mise tools" prompt is prefilled with `starship`, and the plan installs mise and runs `mise use -g starship`

### Requirement: Registry snapshot
The pmox repository SHALL hold a snapshot of mise's registry (name, aliases, description per line) at `internal/bootstrap/mise-registry.tsv`, regenerated by the `bootstrap:mise-registry` task. pmox SHALL write a names-only copy (no descriptions) to `/usr/local/share/devbox-setup/mise-registry.tsv`, keeping the user-data within the 64 KiB snippet limit.

#### Scenario: Snapshot installed
- **WHEN** pmox writes devbox-setup's files to a VM
- **THEN** `mise-registry.tsv` with names and aliases only is written next to `picker.py`, and the user-data stays under 64 KiB
