## Context

**What the `shell` item does today**, in `internal/bootstrap/devbox-setup`:
- installs zsh, oh-my-zsh, powerlevel10k and three plugin repos
  (zsh-fzf-history-search, zsh-autosuggestions, zsh-syntax-highlighting)
- renders `assets/zshrc.tmpl` with a fixed
  `ZSH_PLUGINS="git terraform kubectl aws wd zsh-fzf-history-search zsh-autosuggestions zsh-syntax-highlighting"`

**What `shellcfg` does:** it writes `conf/shell.sh` (zoxide, direnv,
fzf, eza and bat aliases, EDITOR) and sources it at the end of
`.zshrc` and `.bashrc`.

**How tools get on PATH:** most catalog tools are installed through
mise. Their shims are on PATH from `.zshenv` (`add_path_line`), so
`$commands[tool]` is already set when `.zshrc` runs.

**What the oh-my-zsh plugins provide** (checked in an oh-my-zsh
checkout):
- `aws`: wires `complete -C aws_completer aws` only if
  `aws_completer` is on PATH.
- `kubectl`, `helm`, `gh`, `mise`: cache `<tool> completion zsh` into
  `$ZSH_CACHE_DIR/completions`.
- `terraform`, `docker`: ship completion files.
- Each plugin only helps when it is listed in `plugins=()`.

## Goals / Non-Goals

**Goals:**
- Tab completes every catalog tool that ships a zsh completion.
- Fast startup: no completion script generated on a normal start.
- Plugins follow what's installed, including tools added later.
- A nicer Tab menu, offered rather than imposed.

**Non-Goals:**
- Replacing oh-my-zsh or powerlevel10k.
- Bash completion beyond what `docs` (bash-completion) already gives.
- Copying the user's personal functions and aliases (gcm,
  git-make-branch, AWS helpers); those stay theirs.

## Decisions

### D1. Plugins decided when the shell starts

**How:** `zshrc.tmpl` builds `plugins=()` before sourcing oh-my-zsh:
1. Base, always: `git wd sudo extract colored-man-pages
   zsh-fzf-history-search`.
2. Tool plugins, each added when its command exists:

   | plugin | needs command |
   |---|---|
   | `aws` | `aws` |
   | `terraform` | `terraform` |
   | `opentofu` | `tofu` |
   | `kubectl` | `kubectl` |
   | `kubectx` | `kubectx` |
   | `helm` | `helm` |
   | `docker` | `docker` |
   | `gh` | `gh` |
   | `mise` | `mise` |
   | `rust` | `rustup` |
   | `golang` | `go` |

3. Then `fzf-tab` if installed (D4), `zsh-autosuggestions`, and
   `zsh-syntax-highlighting` last.

**Why:** the plugin list follows the tools without devbox-setup
re-rendering `.zshrc` each time a tool is added. Checking `$commands`
costs only a hash lookup.

**Alternative:** render the list from the picks at install time. That
goes stale when a tool is installed by hand or by a later run that
doesn't include `shell`.

### D2. A completion cache for tools without a plugin

**How:** `conf/completions.zsh` is installed at
`~/.config/devbox/completions.zsh` by the `shell` item, and sourced
from `.zshrc` before oh-my-zsh. It holds a table of tool → command that
prints its zsh completion.

**At each shell start:** for each tool on PATH, if
`~/.cache/devbox/zsh-completions/_<tool>` is missing or older than the
tool's resolved binary, the command is run into a temporary file. The
file is moved into place only if it is non-empty and starts with
`#compdef`. The directory is then prepended to `fpath`, and
oh-my-zsh's own `compinit` loads the files.

**When devbox-setup runs `shell`:** it primes the cache, so the first
login doesn't pay for it.

**Staleness:** the resolved binary is `${commands[t]:A}`, following
symlinks. A mise shim therefore compares against the shim, which is
regenerated by `mise reshim` on upgrade. That is good enough to pick
up upgrades.

**Tools in the table**, each command checked to print a `#compdef` script
(nine on the Mac, the rest on an Ubuntu 26.04 VM):

| Tools | Command |
|---|---|
| k9s, argocd, flux, kind, k3d, talosctl, helmfile, kustomize, tilt, skaffold, doctl, hcloud, trivy, golangci-lint, codex | `<tool> completion zsh` |
| stern | `stern --completion zsh` |
| just | `just --completions zsh` |
| task | `task --completion zsh` |
| uv | `uv generate-shell-completion zsh` |
| ruff | `ruff generate-shell-completion zsh` |
| yq | `yq shell-completion zsh` |
| zellij | `zellij setup --generate-completion zsh` |
| deno | `deno completions zsh` |
| pnpm | `pnpm completion zsh` |
| rclone | `rclone completion zsh -` |
| restic | `restic generate --zsh-completion /dev/stdout` |
| watchexec | `watchexec --completions zsh` |

kubecolor isn't in the table: it reuses kubectl's completion through
`compdef` (D5). rustup and cargo are covered by oh-my-zsh's `rust`
plugin.

**HashiCorp-style tools** (`terragrunt`, `vault`, `packer`): these use
`autoload bashcompinit; bashcompinit; complete -o nospace -C <bin>
<bin>`, done after oh-my-zsh runs `compinit` (`completions.zsh` exports
a function the template calls after `source $ZSH/oh-my-zsh.sh`).

**Why:** this keeps oh-my-zsh's single `compinit`, its dump cache and
its security check, with no second `compinit`. The `#compdef` check
keeps a tool that prints help or errors from installing a broken file.

### D3. Ordering in `.zshrc`

The template, in order:
1. `ZSH` and the theme
2. source `completions.zsh`, which updates the cache and extends
   `fpath`
3. build `plugins=()` (D1)
4. `source $ZSH/oh-my-zsh.sh`, which runs `compinit`
5. `devbox_bash_completers`, which sets up the `complete -C` tools
6. powerlevel10k
7. the drop-in source line (`shellcfg`), which stays last, as today

### D4. fzf-tab as its own item

**What:** a new `fzftab` item on the Shell & CLI tab, labelled "zsh
fuzzy Tab completion (fzf-tab)", needing `shell` and `cli`. It clones
`Aloxaf/fzf-tab` into oh-my-zsh's `custom/plugins`. D1 enables it when
that directory exists.

**Settings added by the template when fzf-tab is present:**
- `zstyle ':fzf-tab:complete:cd:*' fzf-preview 'eza -1 --color=always $realpath'`,
  applied only if eza is installed
- `menu no`, which fzf-tab needs, set on both `':completion:*'` and
  oh-my-zsh's more specific `':completion:*:*:*:*:*'`, whose `menu
  select` otherwise wins (found on a VM)

**Why opt-in:** it changes what Tab does, and some people want the
plain zsh menu.

### D5. Tool niceties in `shell.sh`

`conf/shell.sh` adds:
- **terraform or tofu installed:** `export
  TF_PLUGIN_CACHE_DIR="$HOME/.terraform.d/plugin-cache"` and the
  directory is created. Providers are downloaded once per VM instead
  of once per working directory. Taken from the user's zshrc.
- **kubecolor installed:** `alias kubectl=kubecolor`, plus, in zsh,
  `compdef kubecolor=kubectl`, so completion keeps working.

Both run only when the tool is present, like the rest of the drop-in.

## Risks / Trade-offs

- [A tool's completion command hangs, for example by contacting a
  server] → Each generation runs with a 5s timeout (`timeout 5`) and
  keeps the old file on failure.
- [First shell after installing many tools is slow] → devbox-setup
  primes the cache. A shell start after a later upgrade regenerates
  only the stale files.
- [oh-my-zsh's `compinit` dump hides newly added completion files] →
  `completions.zsh` removes `$ZSH_COMPDUMP` whenever it writes a cache
  file, so the next `compinit` rebuilds it.
- [The user edits `.zshrc`] → Unchanged policy: re-running `shell`
  re-renders it and keeps the first original as `.zshrc.orig`. The
  completions drop-in is a separate file, safe to re-run.
